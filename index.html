03 · projects

Dynamic Traffic Light Simulator

In progress

Static timer-based traffic signals waste green time on empty lanes. This project replaces fixed delay()-based cycling with real-time, density-driven signal allocation across four simulated lanes.

How it works

  • Four pre-recorded video feeds simulate lane inputs; each is mapped to its own lane object.
  • OpenCV background subtraction + contour detection converts each frame into a live vehicle count per lane.
  • A priority-scheduler-style controller grants green signal to the highest-density lane, with a weighted timer so low-density lanes still get cleared (no starvation).
  • A Python GUI dashboard shows live vehicle counts, current signal state, and remaining green-time per lane.

Why it's worth reviewing

  • Reuses an OS scheduling concept (priority scheduling + starvation prevention) as the actual control logic for a physical-world system — not just a class exercise.
  • Currently a simulation running on recorded footage; designed to extend to live camera hardware next.
  • Goal: measurably reduce average wait time per lane versus fixed-timer cycling — next step is logging before/after throughput to prove it.

Offline Password & QR Code Generator

Shipped

People reuse weak passwords because strong ones are inconvenient to type and remember. This is a local, fully offline tool that generates high-entropy passwords and hands them back as a scannable QR code.

How it works

  • Modular generation logic (random, string) kept separate from image encoding (qrcode) — swap either without touching the other.
  • Tkinter + ttkbootstrap interface with a light/dark theme toggle and a live QR preview as you generate.
  • Password history persisted locally as JSON, so past credentials aren't lost between sessions.
  • Input validation with explicit ValueError handling — invalid length or config doesn't crash the app.

Why it's worth reviewing

  • End-to-end: generation → encoding → persistence → UI, all in one working local tool.
  • Deliberately offline — no data leaves the device, which is the actual point of a password tool.
  • Good example of defensive coding on user input, not just the happy path.

05 · writing sample

Technical writing

Safe and Secure Password and QR Code Generation

A short technical writeup on the password/QR project, covering the actual engineering decisions rather than just the feature list:

  • Problem framing — reused, weak passwords are a convenience problem before they're a technical problem, which shaped the design around low-friction generation.
  • Modular architecture — generation logic and image/output logic kept in separate modules so either can be modified independently.
  • Fault tolerance — explicit handling of invalid input (length, character-set config) so the app degrades gracefully instead of crashing.
  • Data persistence — password history stored locally in JSON, with no network calls, keeping the tool fully offline by design.
